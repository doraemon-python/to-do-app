# 0002. ブラウザ内保存に localStorage を使う

## 背景

`intent.md` でデータはブラウザ内に保存し、外部送信しない方針が決まっている。1人用・PC 中心・サーバー通信なしの ToDo アプリで、保存するのはテキスト中心のタスクである。保存の具体的な仕組みを決める必要がある。

## 決定

ブラウザ内保存に localStorage を使い、ToDo の一覧を JSON で保存する。読み書きは `src/storage/` に閉じ込め、UI から直接 localStorage を触らない。

## 検討した選択肢

### A. localStorage（採用）

ブラウザ標準で実装が最小。同期 API のため小さなアプリでは扱いやすい。個人用 ToDo の規模なら容量（約 5MB）で足りる見込み。保存処理を小さな層に閉じ込めれば、将来 IndexedDB やサーバーへ移行しやすい。

### B. IndexedDB（不採用）

大量データや構造化データに向くが、今回の規模ではスキーマ管理と非同期処理が過剰。実装・保守の負担が増える。

## 結果・影響

- 実装がシンプルになり、依存ライブラリを増やさずに済む。
- ブラウザの設定やプライベートモードによってデータが消える可能性がある。
- 5MB の容量上限があり、大量の添付データには向かない。
- 複数端末での同期はできない。必要になったら保存方式を見直す。
